## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Слово владельца 28.11.2026, после 08:03 МСК, дословно: «ивентсы кли-схема сверяй.» Форму владелец выбрал 28.11.2026 до 09:48 МСК: время ответа не записал, верно лишь то, что задача заведена в 09:48 в сессии B·30.1.4 — сторожевая сверка в стенд; разовый отчёт и сверка в ./install.sh --check отклонены. Состояние и порядок шагов — хендофф .claude/handoff/bl-hooks-schema-check.md (вне git).

Зачем. Хелпер core/scripts/zcode-hooks.py судит живой ~/.zcode/cli/config.json по EVENTS (семь имён) и трём правилам schema_faults: событие из EVENTS; в слоте только matcher и hooks; список hooks непуст. Список привязан к версии CLI. CLI добавит событие — хелпер откажет в правильном файле (ложная тревога до правки EVENTS). CLI забудет событие из EVENTS — хелпер благословит файл, который CLI отвергает: тот читает весь пользовательский файл пустым, без хуков и плагинов. Сегодня схему CLI с хелпером не сверяет никто: стенд гоняет хелпера на фикстурах, живые бандлы не читает.

Разведка 28.11.2026, 08:15–08:35 (B·30.1.3). Десять объектов events — исходник клона (1), dist ztui (3 слоя), десктопный бандл Resources/glm/zcode.cjs (3), app.asar (3) — во всех ровно семь ключей, равные EVENTS; events strict, ключи слота matcher и hooks, hooks с min(1). Различие внутри бандлов, не между контурами: слой 1 — слот не strict и без transform, слои 2–3 — strict с transform. По ходу разведки десктоп переустановили (3.18.2 → 4.0.0, бандл от 08:04:21), так что версии сторож предполагать не должен. Экстрактор — stands/df3013/schema-probe.py (вне git): слот ищется в том же слое, что events, — короткие имена в минифицированном коде повторяются.

Границы. Сторож живёт только в стенде и видит расхождение лишь при его прогоне — стенд никто не зовёт автоматически. Какой из слоёв разбирает пользовательский файл — не проверено; сторож судит каждый слой. Поля самой записи (command, type) сторож не судит. Хелпер и install.sh не правятся: их сшивка — одна строка.

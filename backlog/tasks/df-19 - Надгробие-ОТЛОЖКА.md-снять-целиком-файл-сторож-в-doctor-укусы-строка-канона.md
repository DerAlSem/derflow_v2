## Description

Решение владельца 24.11.2026, около 16:00 (выбрал из вариантов): **убрать надгробие целиком** — сам файл, его сторож и укусы. Реестр `waiting/` и стартовая дельта не трогаются. Слово «отложка» как термин в каноне остаётся: вариант «заодно переименовать термин» (14 файлов, 52 упоминания) владелец не выбрал.

С чего началось, дословно: «Отложка.мд - это очень плохое название. Почему оно русское? Это надо глобально поправить».

**Что такое надгробие** (проверено по коду, не по документам). `ОТЛОЖКА.md` в корне репо — табличка-переходник на 20 строк: «выведено из обращения», «зови `waiting.py list`», «сюда НЕ дописывать». Последняя правка `6f6181b` (11.09.2026), строк реестра в нём нет. Стартовая дельта идёт не из него: её печатает хук `waiting.py wake`, он читает реестр. Во всём коде файл открывает одно место — `tomb_state()` в `core/scripts/waiting.py`, её зовёт только `doctor`. Файл он ищет в `~/.claude/`, а `install.sh` его туда не раскладывает: с переезда репо 09.11.2026 (`da02750`) сторож не работает — `doctor` печатает красным «надгробие ПРОПАЛО» и выходит с кодом 2. 24.11.2026 проверено: код 2 даёт только эта строка, запись хука и реестр зелёные.

Зачем табличка была: сессия, помнящая старое имя, могла завести отложку заново с чистого листа. Таких сессий нет — имя знали стартовавшие до 11.09.2026.

**Не трогать.** «Надгробие» в другом смысле — надгробие строки реестра, причина смерти done-строки (`waiting.py` :215, :1587, :1629, :1768; `waiting-bite.sh` :831, :1277–1299): это понятие, а не имя файла.

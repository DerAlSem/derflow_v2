## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Родитель — DF-30 (закрыта 27.11.2026). Сессия B·30.3-хуки-zcode после его закрытия задала владельцу три вопроса сверх текста задачи; ответ владельца 28.11.2026, около 00:10 МСК — одной задачей. Состояние и порядок шагов — хендофф `.claude/handoff/bl-hooks-foreign-event.md` (вне git).

Зачем. После DF-30 хелпер `core/scripts/zcode-hooks.py` судит о живом `~/.zcode/cli/config.json` только по записям derflow. Файл, который CLI не читает, он принимает за исправный: чужое событие вне семи имён — `--check` молчит кодом 0, install отвечает «равны — ничего не меняю». По схеме CLI (zcode-cli 0.18.0-2, `adapters/src/config/schema.ts:264–293`, `file-config.adapter.ts:112–119`) такой файл грузится как `config: {}`: без сообщения пропадают все хуки и все плагины всех ztui-сессий. Это чтение исходников; живьём не проверял никто.

Что решено владельцем — три части:

1. Чужое событие. Хелпер замечает в живом файле то, чего нет в схеме CLI, и говорит об этом в обоих режимах; `install` в такой файл не пишет.
2. Выключатель. В строки про `hooks.enabled` дописать, как включить. Сам выключатель `install` по-прежнему не трогает.
3. Шапка стенда. Три строки замеров мутантов кода, которых не хватало критерию #7 задачи DF-30.

Факты (замерено 28.11.2026, около 00:05 МСК, хелпер от `b00ddc7`):

- В копию живого файла вставлено событие `SessionEnd` с чужой записью. `--check` молчит, код 0; `install` — «равны — ничего не меняю», код 0.
- Правила схемы три, и хелпер уже применяет их к эталону — `to_model(..., reference=True)`: событие из семи `EVENTS`; в слоте только `matcher` и `hooks`; список `hooks` непуст. К живому файлу (`to_model(old_hooks, …)` в `run()`) они не применяются.
- Мутанты кода на стенде от `b00ddc7` (25 укусов): m1 «не замечает пропавшей записи» ✅ 13 ❌ 12, все красные из семьи «записи нет»; m2 «не видит расхождения matcher» ✅ 23 ❌ 2; m3 «не снимает лишнюю» ✅ 23 ❌ 2. Чужих красных нет.

Границы. Живой файл сверяется по трём структурным правилам (событие, ключи слота, непустой список), не по полям самой записи: запись без строкового `command` или с неизвестным ключом нарушением не считается, отвергает ли её CLI — по исходникам не сверено. `install.sh` зовёт хелпера одной строкой (`|| drift=1`), коды 1 и 2 там уже обработаны — сшивку `install.sh` не трогать. Список событий привязан к версии CLI: после обновления CLI отказ по чужому событию — ложная тревога до правки `EVENTS`.

## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Найдено 24.11.2026 в DF-19 (сессия C·18.1); слово владельца — чинить, в новой сессии (хендофф C·20, .claude/handoff/waiting-bite-stand-env.md). Оба дефекта дают нечестный результат вместо отказа.

**1. Наследование ZCODE_* (измерено на 9e0dc73, сводится с faa1380).** Из шелла сессии ztui голый `bash core/scripts/waiting-bite.sh` даёт ✅ 220 ❌ 3: три укуса главы «порядок дельты: свой репозиторий печатается первым» красные на любом HEAD. Причина: `here_box()` в `waiting.py` верит `ZCODE_PROJECT_DIR` раньше каталога вызова — нарочно, ZCode стартует хук не обязательно в каталоге сессии. Это решение в коде, не баг. `ZCODE_SESSION_ID` красного не добавляет — только переключает `emit()` на JSON, и `wake` в стенде идёт JSON-строкой. Под `env -u ZCODE_PROJECT_DIR -u ZCODE_SESSION_ID` — ✅ 223 ❌ 0.

**2. Из ворктри без `WAITING=` стенд гоняет живой `~/.claude/scripts/waiting.py`** — симлинк на КОРЕНЬ, не на файл ворктри (`W="${WAITING:-$HOME/.claude/scripts/waiting.py}"`). Зелёный прогон из ворктри проверяет чужой файл и молчит о правке. `install-bite.sh` устроен правильно: берёт `install.sh` рядом с собой (`$HERE`).

**Почему нейтрализация в обёртке вызова, а не `unset` наверху стенда:** так иммунитет проверяется укусом изнутри — переменную можно подложить перед вызовом. `unset` на верхнем уровне укусом изнутри не поймать.

**Не трогать:** `waiting.py` (`here_box()`, `emit()`); JSON-контракт `wake` и порядок по `ZCODE_PROJECT_DIR` уже покрыты `check-hook-emit.py:136` — не дублировать. Шапку «ЗАМЕРЫ» не чистить: старые блоки датированные.

Правка — только `core/scripts/waiting-bite.sh`.

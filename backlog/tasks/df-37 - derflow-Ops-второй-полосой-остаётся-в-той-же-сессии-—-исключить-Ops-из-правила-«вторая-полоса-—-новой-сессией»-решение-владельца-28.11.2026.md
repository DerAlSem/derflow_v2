## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Заведена 28.11.2026 по слову владельца «Заводить, да». До критериев владелец ответил на вопрос, верно ли правило для второй полосы Ops: выбрано «Исключить Ops», как A и D, — около 13:00 МСК; вариант предложен сессией как рекомендация, выбрал владелец. После сборки деплой едет следом, и контекст сборки нужен.

Что мерилось (28.11.2026, пересчёт `cd_r2c.py` и `cd_r2z.py`). Claude Code, 24.09–28.11, 27 сессий с печатью детектора: `hand.sh` в той же реплике человека — 3, все с второй полосой C. Ops 11 из 11, B 7 из 7, Dx 3 из 3, F 1 из 1 — без передачи и без единого упоминания правила. Владелец продолжил в том же табе в 24 из 27; ходов после печати в реплике — медиана 15, контекст на печати — медиана 139k. ZCode с 09.11: 8 печатей, `hand.sh` 4 (C 1 из 1, Ops 2 из 3, B 1 из 4). Для сравнения уровневый порог 300k на Claude Code — 3 из 23, окрик 170k на ZCode — 263 из 307.

Где правило живёт (на 81d618c): `core/skills/derflow/SKILL.md`, раздел «Вторая полоса в сессии — новой сессией»; `core/hooks/context-meter.py` — `STAY = ("A", "D")` (строка 51), комментарий над ним (46–49), сработка (303); `core/skills/derflow/_capture.md` (строка 120); рассказ `core/skills/derflow/archive/lane-cost-rules-promoted.md` (строки 25 и 90 — текст 14.09, не переписывать); стенд `core/scripts/check-context-meter.py`.

Канон правится read-modify-write по якорю (`derflow/_editing.md`), источник — `core/skills/derflow/SKILL.md`; после правки `./install.sh`, иначе `--check` покажет отставший generated.

Что решение не покрывает. В замере Ops второй полосой шла и без сборки перед ней; решение владельца сформулировано для второй полосы Ops целиком, без условия «после сборки». Владелец подтвердил 28.11.2026 такую формулировку (пункт 3 отчёта). B и Dx второй полосой остаются под правилом, хотя их слушают так же (24 из 27 молчат); отдельного решения о носителе для них владелец не принимал. Тот же файл и тот же стенд правит DF-36 — не параллить.

Как `waiting.py doctor` проверяет, жив ли механизм реестра, — по факту кода на
24.11.2026 (DF-19). `doctor` — команда для человека, а не хук: своё отсутствие
стартовая дельта не видит по построению. Об остальном реестре говорит шапка
`core/scripts/waiting.py`.

Без `--install` `doctor` ничего не меняет: код 0, если поломок нет, код 2 — при
любой найденной. Проверяются две вещи:

1. Запись хука `SessionStart` в `~/.claude/settings.json` — разбором JSON, а не
   поиском по тексту.
2. Реестр и его фон: не молчит ли то, что фон обязан спрашивать.

Строки «·» и замер TTL — сведения, в код возврата они вклада не кладут.

Предел: `doctor` читает только `~/.claude/settings.json`. Запись того же хука в
`~/.zcode/cli/config.json` он не проверяет — её сверяет `./install.sh --check`
(doc-4).

### Requirement: `doctor` судит о записи хука разбором, а не поиском по тексту

Подстрока `waiting.py wake` живёт и в `permissions.allow`. Поиск по файлу сказал
бы «на месте» при мёртвом хуке.

#### Scenario: запись на месте

КОГДА в `~/.claude/settings.json` в живом блоке `SessionStart` есть хук с
командой `waiting.py wake`, ТОГДА `doctor` печатает «✅ запись хука SessionStart
на месте».

#### Scenario: записи нет

КОГДА файла нет, он не читается, не разбирается как JSON или команды
`waiting.py wake` в нём нет, ТОГДА `doctor` печатает строку с 🔴 и причиной, а
для отсутствующей записи — ещё и команду `waiting.py doctor --install`. Код 2.

#### Scenario: команда упомянута вне живого блока

КОГДА строка `waiting.py wake` в файле есть, а в блоке `SessionStart` её нет,
ТОГДА `doctor` печатает «🔴 команда wake в настройках упомянута, но НЕ в живом
блоке SessionStart» с советом разобрать руками, куда она попала. Код 2.

### Requirement: `doctor --install` вставляет запись хука по якорю и не переписывает файл

Файл правят несколько сессий разом. Сериализация `json.load → json.dump`
переписала бы его целиком и затёрла чужую главу молча.

#### Scenario: вставка

КОГДА строка `"hooks": {` в файле одна и записи `waiting.py wake` нет, ТОГДА
блок хука встаёт сразу после строки-якоря, остальное остаётся байт в байт, файл
заменяется целиком через временный файл с pid в имени. Код 0.

#### Scenario: запись уже стоит

КОГДА строка `waiting.py wake` в файле уже есть, ТОГДА `--install` печатает
«запись хука уже на месте — ничего не меняю». Код 0.

#### Scenario: ключ `SessionStart` уже есть, а записи в нём нет

КОГДА в файле есть ключ `SessionStart` без нашей записи, ТОГДА `--install`
отказывает кодом 2 и печатает команду для вставки руками: второй одноимённый
ключ разбор молча выбрасывает, и хук был бы выключен.

#### Scenario: якорь не единственный

КОГДА строка `"hooks": {` найдена не один раз, ТОГДА `--install` отказывает
кодом 2 и печатает блок для вставки руками.

#### Scenario: файл не читается

КОГДА `~/.claude/settings.json` не читается, ТОГДА `--install` отказывает
кодом 2 с причиной.

### Requirement: `doctor` отличает молчащий реестр от пустого

Если проба падает при старте, кэш перестаёт обновляться, дельта пуста, `list`
печатает вчерашнюю правду — и тревоги нет. О состоянии фона говорит квитанция
`~/.claude/waiting-cache/_run.json`, её пишет держатель замка пробы.

#### Scenario: фон отчитался

КОГДА квитанция цела и свежая, ТОГДА `doctor` печатает «✅ фон отчитался
<время>: строк <N>, недостижимых <M>».

#### Scenario: фон не отчитывался дольше трёх TTL

КОГДА в реестре есть строка, которую фон обязан спрашивать, — оформленная, не
`taken` и не `done`, с пробой не `none`, — а квитанция старше трёх
`CACHE_TTL_S` (трёх часов), ТОГДА `doctor` печатает «🔴 фоновая проба не
отчитывалась <N> ч — реестр печатает вчерашнюю правду». Код 2.

#### Scenario: спрашивать нечего

КОГДА строк, которые фон обязан спрашивать, нет, ТОГДА возраст квитанции
поломкой не считается.

#### Scenario: прогон оборван или квитанция сломана

КОГДА в квитанции стоит `stale_lock_broken` (замок сняли протухшим) или нет
времени `finished_at_ts`, ТОГДА `doctor` печатает 🔴 с причиной. Код 2.

#### Scenario: прогонов ещё не было

КОГДА квитанции нет или она не читается, ТОГДА `doctor` печатает «· фоновых
прогонов ещё не было — это не поломка, это старт». Код не меняется.

### Requirement: замок пробы и замер TTL — сведения, а не поломка

#### Scenario: замок занят

КОГДА каталог `~/.claude/waiting-lock` существует, ТОГДА `doctor` печатает
«· замок пробы занят <N> с (TTL 900)». Код не меняется.

#### Scenario: замер TTL

КОГДА в кэше есть счётчики прогонов `same_truth_runs` и `changed_runs`, ТОГДА
`doctor` печатает долю смен исхода и подпись: это частота событий в мире, а не
довод о `CACHE_TTL_S`. Код не меняется.

Как стенд `core/scripts/waiting-bite.sh` выбирает файл под испытанием и в какой среде его запускает, — по факту кода (DF-20; укус про файл дополнен статической половиной в DF-22, 25.11.2026; два её хвоста закрыты в DF-23 и DF-24, 25.11.2026). Правило укуса и таблицы замеров — в шапке самого стенда; про `waiting.py` — его шапка и doc-5.

Стенд macOS-only (`date -v`), один прогон около 25 с. Дом, ящики и корни скана подменяются: `WAITING_HOME` указывает в mktemp-каталог, живой `~/.claude` стенд не трогает.

Запуск:

    bash core/scripts/waiting-bite.sh
    WAITING=/путь/к/копии bash core/scripts/waiting-bite.sh

### Requirement: испытываемый файл — рядом со стендом

`W="${WAITING:-$HERE/waiting.py}"`, где `HERE` — физический каталог самого стенда (`cd -P "$(dirname "$0")"`, тот же приём, что `$HERE` в `install-bite.sh`). От каталога запуска выбор не зависит.

Первая строка прогона называет испытываемый файл и почему именно он:

    испытываемый файл: <путь> — рядом со стендом
    испытываемый файл: <путь> — по WAITING=

#### Scenario: стенд пущен из ворктри

КОГДА стенд запущен из ворктри без `WAITING=`, ТОГДА испытывается `waiting.py` ворктри: сломанный файл ворктри краснит прогон из ворктри, а прогон из корня в тот же момент зелёный. Замер 25.11.2026 (DF-22): поломка — `unacked` возвращает True; из ворктри ✅ 222 ❌ 4, стенд корня в тот же момент ✅ 226 ❌ 0. После влития повтор новым стендом из корня: из корня ✅ 226 ❌ 0, из ворктри ✅ 222 ❌ 4.

Стенд после DF-23 и DF-24 дал те же числа: из ворктри ✅ 222 ❌ 4 (те же четыре укуса), стенд корня в тот же момент ✅ 226 ❌ 0. Повтор из корня после влития (25.11.2026) дал те же числа, что из ворктри: живой ✅ 226 ❌ 0 из ztui и из чистой среды, выводы равны; молчащая заглушка ✅ 0 ❌ 226; сломанная копия ✅ 222 ❌ 4; три копии с решёткой внутри строки, воронка на абсолютный путь, первый вызов мимо воронки и три формы запуска — ✅ 225 ❌ 1; вызов в комментарии внутри подстановки и «<<» внутри строки — ✅ 226 ❌ 0.

#### Scenario: подмена копией

КОГДА `WAITING` указывает на нарочно сломанную копию, ТОГДА краснеют укусы, которых касается поломка; заглушка (`print` + `exit 0`) даёт ✅ 0. Молчащая заглушка (`exit 0` без печати) тоже даёт ✅ 0 ❌ 226 (замер 25.11.2026, DF-23); до правки она давала ✅ 4 ❌ 222, потому что зелеными стояли четыре «пустые» половины пар «wake — ноль байт». В каждый из четырёх укусов внесена положительная половина, новых укусов нет. Перед `wake` стенд кладёт квитанцию дельты `<id>.seen.json`, а работающий `wake` её сносит: он обслуживает квитанции всех строк до раннего возврата. В третьем укусе (сломанный конфиг корней) `wake` падает внутри и ничего не трогает, поэтому свидетелем взят `list` на том же входе: он обязан отказать кодом 2. Поломка копии (`unacked` возвращает True) эти четыре укуса не задевает, у сломанной копии те же четыре красных, что в DF-20.

#### Scenario: укус на сам выбор файла

КОГДА стенд запущен с путём по умолчанию `~/.claude/scripts/waiting.py` (симлинк на корень), ТОГДА краснеет укус «испытываемый файл — рядом со стендом (или назван WAITING=), и он же завёл строку» — единственный, кто видит подмену. Замер 25.11.2026: копия стенда с `W="$HOME/.claude/scripts/waiting.py"` — ✅ 225 ❌ 1.
Укус «испытываемый файл — рядом со стендом (или назван WAITING=), и он же завёл строку» держат три связки: путь равен определению по умолчанию либо назван `WAITING=` (живая половина), причина обхода пуста (статическая), и тот же файл завёл строку (положительная — заглушке зеленеть нечего).

Статическая половина (25.11.2026, DF-22) стоит у определения `W`. Стенд читает собственный текст (`awk`). Комментарий срезается там, где его начинает bash: `#` в начале строки либо после пробела, вне кавычек своего уровня (DF-24, 25.11.2026). Сканер держит стек контекстов: уровень 0 — сама строка скрипта, каждое открытое `$(…)`, `<(…)` или `>(…)` — свой уровень со своей кавычкой; состояние переносится через строки. До правки срез шёл по первому « #» независимо от кавычек. Срезанная строка читается до поиска открывателя heredoc, тело heredoc не читается до строки, равной тегу. Тела пропускать обязательно: фикстуры `settings.json` лежат в `<<'SETT'` и несут строку `python3 $HOME/.claude/scripts/waiting.py wake` — это содержимое файла, а не вызов. Каждый запуск `python` или `python3` ведёт на `"$W"` либо читает программу не из файла: `-` из stdin, аргумент с началом `-c` — из аргумента.

#### Scenario: вызов мимо переменной пути

КОГДА хотя бы один запуск интерпретатора идёт не через `"$W"` и не читает программу из stdin либо аргумента, ТОГДА краснеет один укус «испытываемый файл», с причиной `запуск мимо переменной пути: <токен>`. До правки первый вызов мимо `wp()` был зелёным: ✅ 226 ❌ 0 — живая половина сравнивала переменную с её же определением.

Замер 25.11.2026: копии стенда лежали рядом с рабочей копией `waiting.py`.

| копия стенда | итог |
|---|---|
| воронка `wp()` — на абсолютный путь корня | ✅ 225 ❌ 1 |
| первый вызов мимо воронки — на `$HOME/.claude/scripts/waiting.py` | ✅ 225 ❌ 1 |
| он же — на `"$HERE/waiting.py"` | ✅ 225 ❌ 1 |
| он же — `/usr/bin/python3` и путь через `$HOME` | ✅ 225 ❌ 1 |
| он же после `echo "x # y"` на той же строке | ✅ 225 ❌ 1 |
| он же после `X="a # b";` вне подстановки | ✅ 225 ❌ 1 |
| он же после `echo 'x # y'` в одинарных кавычках | ✅ 225 ❌ 1 |
| он же только упомянут в комментарии внутри многострочной `$(…)` | ✅ 226 ❌ 0 |

В каждой строке красен ровно укус «испытываемый файл», кроме последней: упоминание в настоящем комментарии не вызов, краснеть там нечему. Три строки с решёткой внутри строки до DF-24 давали ✅ 226 ❌ 0, ложное зелёное тихое.

#### Scenario: стенд запущен не файлом

КОГДА стенд запущен через `bash -s` со стендом на stdin, `source` из другого скрипта либо `bash -c`, ТОГДА краснеет тот же укус с причиной `не прочитал свой текст: <$0>`: файл выбирает каталог запуска, а не чекаут стенда. Замер 25.11.2026: ✅ 225 ❌ 1 в каждой из трёх форм.

Пределы, измерены 25.11.2026. Путь к файлу аргументом после программы `-c` не виден — ✅ 226 ❌ 0. Голое имя `waiting.py` ловится статической половиной, но живую не сохранить: имя ищется в cwd. Воронка через `$HOME` краснит ещё пробу «entry сокращает домашний каталог до ~» — она подменяет `HOME`. Текст внутри строки вне heredoc читается как код — ложное красное громкое. `<<` внутри строки открывает ложный heredoc: копия, где между `echo "x <<true y"` и строкой `true` стоит вызов мимо на `~/.claude/…`, даёт ✅ 226 ❌ 0, ложное зелёное тихое (DF-25, не чинен). Незакрытое тело heredoc и отказ `awk` краснят, а не молчат; с DF-24 так же красят незакрытые к концу текста кавычка и подстановка, каждый случай ✅ 225 ❌ 1, с причиной «кавычка не закрыта к концу текста» либо «подстановка не закрыта к концу текста»: сканер разошёлся с bash и дальше читает в чужом состоянии.

### Requirement: переменные сессии ZCode не доходят до waiting.py

Каждый запуск `waiting.py` стенд делает через `env -u ZCODE_PROJECT_DIR -u ZCODE_SESSION_ID`: обёртка `wp()` для всех вызовов через `wt()` и напрямую мимо него, и та же приставка у python-обёртки таймера в `wake_ms`. Снимаются в обёртке, а не `unset` наверху стенда: так иммунитет проверяется укусом изнутри.

`here_box()` в `waiting.py` верит `ZCODE_PROJECT_DIR` раньше каталога вызова нарочно: ZCode стартует хук не обязательно в каталоге сессии. Для хука это правильно; стенд же задаёт порядок дельты каталогом вызова. `ZCODE_SESSION_ID` переключает вывод `wake` на JSON, а стенд читает plain.

#### Scenario: стенд пущен из шелла сессии ztui

КОГДА стенд запущен из шелла сессии ztui без подготовки, ТОГДА его счёт равен счёту того же стенда под `env -u ZCODE_PROJECT_DIR -u ZCODE_SESSION_ID` на том же HEAD.

#### Scenario: укус подкладывает ZCODE_PROJECT_DIR

КОГДА перед `wt … wake` подложен `ZCODE_PROJECT_DIR` с настоящим чужим репозиторием, ТОГДА порядок дельты остаётся по каталогу вызова: строки вызванного репозитория первыми, заголовок «этот репозиторий» на месте.

#### Scenario: укус подкладывает ZCODE_SESSION_ID

КОГДА перед `wt … wake` подложен `ZCODE_SESSION_ID`, ТОГДА вывод остаётся plain: дельта напечатана строками, а не одной JSON-строкой.

Как стенд `core/scripts/waiting-bite.sh` выбирает файл под испытанием и в какой среде его запускает, — по факту кода (DF-20). Правило укуса и таблицы замеров — в шапке самого стенда; про `waiting.py` — его шапка и doc-5.

Стенд macOS-only (`date -v`), один прогон около 25 с. Дом, ящики и корни скана подменяются: `WAITING_HOME` указывает в mktemp-каталог, живой `~/.claude` стенд не трогает.

Запуск:

    bash core/scripts/waiting-bite.sh
    WAITING=/путь/к/копии bash core/scripts/waiting-bite.sh

### Requirement: испытываемый файл

`W="${WAITING:-$HOME/.claude/scripts/waiting.py}"`. Без `WAITING=` это симлинк на живой файл корня канона, с `WAITING=` — названная копия. От каталога запуска и от того, где лежит сам стенд, выбор не зависит.

#### Scenario: стенд пущен из ворктри

КОГДА стенд запущен из ворктри без `WAITING=`, ТОГДА испытывается файл КОРНЯ, а не файл ворктри: зелёный прогон ничего не говорит о правке ворктри.

#### Scenario: подмена копией

КОГДА `WAITING` указывает на нарочно сломанную копию, ТОГДА краснеют укусы, которых касается поломка; заглушка (`print` + `exit 0`) даёт ✅ 0.

### Requirement: среда запуска

`waiting.py` запускается с той средой, в которой стартовал стенд. Переменные сессии ZCode доходят до него целиком: `ZCODE_PROJECT_DIR` задаёт «свой репозиторий» в порядке дельты раньше каталога вызова, `ZCODE_SESSION_ID` переключает вывод на JSON.

#### Scenario: стенд пущен из шелла сессии ztui

КОГДА стенд запущен из шелла сессии ztui без подготовки, ТОГДА три укуса главы «порядок дельты: свой репозиторий печатается первым» красные на любом HEAD (✅ 220 ❌ 3 на `9e0dc73`), а под `env -u ZCODE_PROJECT_DIR -u ZCODE_SESSION_ID` — ✅ 223 ❌ 0.

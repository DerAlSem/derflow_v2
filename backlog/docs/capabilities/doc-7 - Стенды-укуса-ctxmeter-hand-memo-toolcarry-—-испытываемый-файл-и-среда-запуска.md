Как четыре стенда-укуса — `core/scripts/ctxmeter-bite.sh`, `hand-bite.sh`, `memo-bite.sh`, `toolcarry-bite.sh` — выбирают файл под испытанием и в какой среде его запускают, — по факту кода (DF-21). Правило укуса и таблицы замеров — в шапках самих стендов; про пятый стенд, `waiting-bite.sh`, — doc-6.

Запуск, у всех четырёх одна форма:

    bash core/scripts/<стенд>.sh
    <VAR>=/путь/к/копии bash core/scripts/<стенд>.sh

Фикстуры — в mktemp-каталоге: живые транскрипты и вердикты стенды не трогают.

### Requirement: испытываемый файл

`<файл>="${<VAR>:-$HOME/.claude/<каталог>/<файл>}"`. `~/.claude/scripts` и `~/.claude/hooks` — симлинки на живой корень канона, `core/scripts` и `core/hooks`.

| стенд | VAR | файл по умолчанию |
|---|---|---|
| `ctxmeter-bite.sh` | `METER` | `~/.claude/hooks/context-meter.py` |
| `hand-bite.sh` | `HAND` | `~/.claude/scripts/hand.sh` |
| `memo-bite.sh` | `MEMO` | `~/.claude/scripts/memo.py` |
| `toolcarry-bite.sh` | `TOOLCARRY` | `~/.claude/scripts/toolcarry.py` |

Без `VAR` это файл КОРНЯ канона, с `VAR` — названная копия. От каталога запуска и от того, где лежит сам стенд, выбор не зависит.

#### Scenario: стенд пущен из ворктри

КОГДА любой из четырёх стендов запущен из ворктри без переменной подмены, ТОГДА испытывается файл КОРНЯ, а не файл ворктри: зелёный прогон ничего не говорит о правке ворктри. На `6369d63` сломанный испытываемый файл ворктри (путь не подменён) даёт и из ворктри, и из корня одинаковый зелёный счёт: ✅ 7 ❌ 0, ✅ 20 ❌ 0, ✅ 64 ❌ 0, ✅ 14 ❌ 0.

#### Scenario: подмена заглушкой

КОГДА переменная подмены указывает на заглушку (молчит, exit 0), ТОГДА `ctxmeter-bite.sh` даёт ✅ 0 ❌ 7, `toolcarry-bite.sh` — ✅ 0 ❌ 14, `memo-bite.sh` — ✅ 0 ❌ 64, а `hand-bite.sh` — ✅ 2 ❌ 18: два его укуса с обратной иголкой («предупреждения быть НЕ должно») — отрицание без положительной половины, и заглушка проходит их даром.

### Requirement: среда запуска

Ни один из четырёх не называет испытываемый файл. Первая строка прогона — заголовок первой главы (`=== порог, защёлка и живучесть… ===`, `=== RED: то, ради чего гейты и стоят ===`, `=== положение в git ===`, `=== нарезка ходов, новизна токена и окно ===`), последняя — `итог: ✅ N ❌ M`.

Среда у каждого своя:

- `ctxmeter-bite.sh`: `HOME` подменён на mktemp-каталог с `.claude/state` — защёлки не в живом доме; остальная среда наследуется. `context-meter.py` опознаёт ZCode по `ZCODE_SESSION_ID`: вывод JSON `{"additionalContext": …}`, пороги 130k и 170k вместо 150k и 300k, текст зовёт `~/.zcode/scripts/hand.sh`.
- `hand-bite.sh`: `hand.sh -n`, сухой прогон — табов не открывает; из живого трогает только `${TMPDIR}/derflow-hand/`. Переменных сессии на сухом пути не читает.
- `memo-bite.sh`: `MEMO_HOME` указывает в mktemp-каталог — вердикты не в живой `~/.claude`. `CLAUDE_CODE_SESSION_ID` — метка сессии вердикта; стенд задаёт её явно там, где она иголка.
- `toolcarry-bite.sh`: `toolcarry.py` среду не читает.

#### Scenario: стенд пущен из шелла сессии ztui

КОГДА любой из четырёх стендов запущен из шелла сессии ztui без подготовки, ТОГДА его счёт равен счёту в чистой среде (без `ZCODE_*` и `CLAUDE_*`) на том же HEAD — на `6369d63` в обоих случаях ✅ 7 ❌ 0, ✅ 20 ❌ 0, ✅ 64 ❌ 0, ✅ 14 ❌ 0. Но `ctxmeter-bite.sh` при этом проверяет контракт ZCode, а не Claude Code: иголки «hand.sh» и «420k» переживают JSON-строку, и какой контракт проверен, зависит от того, из какого шелла позвали.

Какая модель что видит — по факту кода на 23.11.2026 (DF-14, DF-15). С 23.11.2026
GLM-среды переведены на glm-5.4 (в zcode glm-5.3 и Flash остаются выбираемыми
в `/model`), картинку читает сама модель сессии, упора от слепоты нет ни в одной
среде.

Слепота стоила боя 04.10.2026: glm-5.3 в rk_bot «прочитал» скриншот psql, которого
не видит, и выдал выдуманную таблицу с вердиктом «фискального долга нет». Отсюда
правило: «вижу на скрине» — факт пробы, а не слово о модели.

## Среды

| Среда | Модель сессии | Картинку читает | Упор от слепоты |
|---|---|---|---|
| zcode (ztui, десктоп) | glm-5.4 · glm-5.3 · glm-5.3-Flash (`/model`) | 5.4 — сам через `Read` (проба); 5.3-Flash — сам (так работал агент `vision`); 5.3 — нет | нет; агент `vision` распущен 23.11.2026 |
| Claude Code через `scripts/glm.sh` | glm-5.4 | сам через `Read` (проба) | нет — хук, отклонявший `Read` картинки, снят 23.11.2026 |
| opencode | `zai-glm/glm-5.4` (`~/.config/opencode/opencode.json`) | сам (проба) | нет — `plugins/derflow-hooks.js` картинки не трогает |
| kimi-code, kimi-work | kimi (`image_in`) | сам | нет |
| Claude Code на Claude | Claude | сам | нет |

**opencode.** Кроме картинок модель описана с модальностями `video` и `pdf` и читает
их тоже сама. Pdf (текстовый, с кодом) и видео (6 с, код в кадре) прочитаны прямым
запросом к coding-эндпоинту z.ai 23.11.2026; сканы pdf не проверялись. Аудио
моделью не описано — что бывает с аудиофайлом в промпте, не проверялось.

**Почему упора больше нет.** Он был завязан на среду, а не на модель: хук Claude
Code — на метку `DERFLOW_HOST=glm`, «внешние глаза» opencode срабатывали на любую
картинку промпта. На видящей модели такой упор не защищает, а вредит — заблокировал
бы `Read` картинки или подменил собственное зрение модели транскрипцией текстовой.
Поэтому перевод на glm-5.4 и снятие упора сделаны одной задачей в каждой среде.

## Проба: `scripts/check-vision.py`

    check-vision.py new              # рендерит картинку со случайным содержимым, печатает путь и схему ответа
    check-vision.py check <каталог>  # сверяет answer.json с истиной; код 0 = все поля сошлись

Восемь полей: код заголовка, таблица 3 × «имя — сумма — статус», строка ошибки
с hex-идентификатором, моноширинный блок как вывод psql и его футер, счёт фигур
по цвету, форма фигур, серийный номер кеглем 11 px. Содержимое живёт только в
пикселях: html удаляется после рендера, истина лежит в `truth.json`, которого
читающий не открывает. Рендерит `scripts/shot.mjs`.

Замер 23.11.2026, ztui, glm-5.4: три картинки, 23 поля из 24 дословно. Промах —
последняя буква серийного номера 11 px (S прочитана как 5); тот же файл через
прямое API glm-5.3-flash дал ту же ошибку. opencode, glm-5.4: прямой запрос без
инструментов — 7 полей из 8, промах снова серийный номер. Живые прогоны opencode и
Claude Code через `glm.sh`, где модель сама увеличила фрагменты, — 8 из 8; в opencode
второй ход той же сессии с картинкой в истории прошёл.

### Requirement: Право «вижу на скрине» даёт проба

Модель сессии считается видящей, пока для неё есть «читает» в таблице выше,
подкреплённое пробой.

#### Scenario: сменилась модель сессии

КОГДА сессия стартует на модели, у которой в таблице нет «читает» с пробой,
ТОГДА картинка не описывается по впечатлению: гоняется `check-vision.py new` →
`Read` → `check`, и по результату дополняется строка среды в этой доке.

#### Scenario: сессия zcode на glm-5.4 получает картинку

КОГДА сессия zcode на glm-5.4 читает изображение через `Read`, ТОГДА она
работает с увиденным напрямую: агент `vision` не существует, передачи картинки
другому агенту или скрипту нет.

#### Scenario: сессия zcode на glm-5.3 получает картинку

КОГДА сессия zcode работает на glm-5.3, ТОГДА она говорит «картинку не вижу» и
просит текст либо перевод сессии на glm-5.4 (`/model`): упора хуком в zcode нет,
внешнего описания картинки тоже нет, правило держится слотом `models`.

#### Scenario: среда переводится на видящую модель

КОГДА в среде, где стоял упор от слепоты, моделью сессии становится модель с
«читает» в таблице выше, ТОГДА упор снимается той же задачей, что и перевод:
упор завязан на среду (метку хоста, имя плагина), а не на модель, и на видящей
модели подменит её собственное зрение транскрипцией текстовой.

### Requirement: Мелкий шрифт не считается прочитанным

#### Scenario: критичный идентификатор виден только мелким шрифтом

КОГДА номер, код или сумму нужно снять с картинки, а текст на ней кеглем около
11 px при одинарной плотности, ТОГДА значение сверяется вторым источником
(текстом из интерфейса, выводом команды) и до сверки в
вердикт не идёт.

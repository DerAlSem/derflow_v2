# Бриф для агента среды: подключить derflow к своей среде

Ты — агент, который работает в среде, отличной от Claude Code: ztui / ZCode,
Kimi или другой. Владелец хочет, чтобы derflow работал у тебя так же, как в
Claude Code. Документ — вводные. Утверждения, помеченные «проверено», сняты
живым прогоном 09.11.2026. Остальное — гипотезы, проверь их до того, как на них
опираться.

## 1. Что такое derflow и где он лежит

Это процесс разработки: роутер задач (скилл `derflow`), docs-first поверх
Backlog.md (скилл `docflow`), скрипты, хуки, агенты-исполнители и критики,
глобальные инструкции. Источник правды — git-репо **`~/dev/derflow`**
(remote `DerAlSem/derflow_v2`, **публичный**).

```
core/            канон, один на все среды
  AGENTS.md      глобальные инструкции со слотами <!-- slot:имя --> … <!-- /slot -->
  skills/        derflow, docflow
  scripts/ hooks/ schemas/ agents/
skills/          скиллы-спутники (ru-text, copywriting, explore-code, …)
hosts/<среда>/   только то, чем среда правда отличается
  slots/<имя>.md    подмена слота входного файла
  agents/<имя>.head подмена шапки (frontmatter) агента; <имя>.md — свой агент целиком
  scripts/ hooks/ plugins/ …  свои обвязки среды
  generated/        сборка tools/build.py — руками НЕ править
tools/build.py   сборка входных файлов и агентов
install.sh       сборка + симлинки во все среды; --check — только отчёт о дрейфе
```

Живые каталоги сред — **симлинки в чекаут `~/dev/derflow`**. Правка канона
действует сразу, правка слота или шапки агента — после `./install.sh`.

## 2. Как подключены среды сейчас

| Что | Claude Code | ZCode / ztui | opencode |
|---|---|---|---|
| входной файл | `~/.claude/CLAUDE.md` → `hosts/claude/generated/CLAUDE.md` | `~/.zcode/AGENTS.md` → `hosts/zcode/generated/AGENTS.md` | `~/.config/opencode/AGENTS.md` → `hosts/opencode/AGENTS.md` (свой, не из слотов) |
| скиллы | `~/.claude/skills/<x>` → `core/skills/<x>`, `skills/<x>` | `~/.zcode/skills/<x>` → то же | — |
| агенты | `~/.claude/agents` → `core/agents` | `~/.zcode/agents/<x>.md` → `hosts/zcode/generated/agents/` (шапки: модель GLM-5.3-Flash, `thoughtLevel`, урезанные `tools`) | — |
| хуки | `~/.claude/settings.json` (реальный файл, не симлинк) → `~/.claude/hooks/*`, `~/.claude/scripts/*` | `~/.zcode/cli/config.json` (НЕ под install.sh) → те же `~/.claude/hooks/*` + `~/.zcode/hooks/tariff-meter.py` | плагин `plugins/derflow-hooks.js` вызывает `~/.claude/hooks/*`, `~/.claude/scripts/*` |
| расщепление сессии | `~/.claude/scripts/hand.sh` | `~/.zcode/scripts/hand.sh` → `hosts/zcode/scripts/hand.sh` | `scripts/hand.sh` |

`~/.claude/scripts`, `hooks`, `skills/*` — симлинки в `~/dev/derflow/core`.
Поэтому абсолютные пути `~/.claude/scripts/...` из любой среды верны.

## 4. Твоя задача

Сначала выясни по своей среде пять фактов. Каждый факт — с доказательством:
путь к файлу, строка исходника или вывод команды. «Я думаю» фактом не считается.

1. **Глобальные инструкции:** какой файл грузится в каждую сессию, есть ли слой проекта.
2. **Скиллы:** из каких каталогов и в каком порядке обнаруживаются, идёт ли сканер по симлинкам, что выключает скилл (конфиг, длина описания, ключи шапки). Для ztui главное — почему не виден ни один пользовательский скилл.
3. **Агенты и сабагенты:** где лежат определения, формат шапки (поля модели, инструментов, уровня мышления), какие модели доступны.
4. **Хуки:** какие события есть (старт сессии, отправка промпта, до и после инструмента), где они настраиваются, что приходит на stdin и как вывод хука попадает в контекст.
5. **Новая сессия или таб из сессии:** чем открыть новую сессию со стартовым промптом в нужном каталоге. Это нужно для `hand.sh`.

Потом предложи адаптер среды в рамках правил ниже.

## 5. Правила правки

- Канон (`core/`) не форкать под среду. Отличие среды — слот в `core/AGENTS.md` + файл в `hosts/<среда>/slots/`, или `.head` агента, или своя обвязка в `hosts/<среда>/`. Новая среда — новый `hosts/<имя>/` и блок в `install.sh`; новая среда с входным файлом из слотов — ещё строка в `HOSTS` у `tools/build.py`.
- `hosts/*/generated/` и живые файлы (`~/.zcode/AGENTS.md` и т. п.) руками не править: после правки источника — `./install.sh`, потом `./install.sh --check` → «✅ дрейфа нет». Коммитить источник вместе с generated.
- Репо публичный: никаких ключей, хостов и токенов. Скрипты читают ключи из конфигов среды при запуске (как `glm-usage.mjs` и `derflow-hooks.js`).
- `~/dev/derflow` правят несколько сессий разом, а ворктри не изолирует: живые среды читают основной чекаут. Правка — read-modify-write по точному якорю, никогда перезапись файла целиком; `git status` до и после, коммит мелкий.
- Задачи — через docflow (`backlog` CLI в `~/dev/derflow`), по ztui — `DF-2`.
- Чего не знаешь — так и пиши: «⚠️ НЕ проверено — что, риск».

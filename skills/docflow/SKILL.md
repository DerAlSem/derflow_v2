# docflow — docs-first поверх Backlog.md

Четыре колонки, у каждой один смысл:

| Колонка | Смысл | Где правда |
|---|---|---|
| **Done** | как устроено | `backlog/docs/capabilities/<capability>.md` — НЕ закрытые тикеты |
| **In Progress** | кто что держит | замок `bl-lock.sh`; статус лишь показывает его |
| **To Do** | что доделать | задача с критериями приёмки |
| **Backlog** | не сейчас | причина + когда: Due Date и/или блок пробы ```when |

Закрытый тикет — история. «Как устроено» живёт только в доке capability, и
задача не закрывается, пока дока не обновлена: это держит `bl-done.sh`.

Работа с задачами, доками и статусами — только через `backlog` CLI (он сам
велит читать `backlog instructions <фаза>`). Где его инструкции расходятся с
этим файлом — прав этот файл.

## Поток

**0. Не работа.** Вопрос «как устроено X» → `backlog doc search "X" --plain`,
читай доку, отвечай. Механическая правка, где думать не о чем (опечатка,
значение конфига) → делай сразу, без задачи.

**1. Сначала смотри.** `backlog doc search` по capability · `bl-lock.sh who` ·
`backlog search "<тема>" --plain`. Задача уже есть — бери её, не плоди.

**2. Новая задача — это контракт ревью.** Критерии приёмки (`--ac`) пишутся
так, чтобы владелец проверял их, а не дифф построчно: наблюдаемое поведение,
по одному факту на пункт. Задача больше, чем владелец отревьюит за ~15 минут,
— режь на подзадачи (`-p <родитель>`). Двусмысленно, или деньги, авторизация,
перс-данные, публичный контракт, миграция схемы → сначала критерии с
владельцем (`superpowers:brainstorming`), его итог кладётся в описание и план
задачи, а не в `docs/superpowers/specs`.

**3. Взять.** `~/.claude/scripts/bl-lock.sh take <ID> [кто]`. Отказ кодом 3 —
задачу держит другая сессия: не трогай, бери другую или спроси владельца.
Параллельный репо — ворктри до первой правки (`derflow/_parallel.md`).

**4. Делать.** Ты оркеструешь; реализация по ясной форме — исполнителю на
Sonnet (`python-pro`, `frontend-developer`) с ТЗ «что, где, готово = AC».
Диагностику делай сам (`superpowers:systematic-debugging`): контекст поиска и
есть работа. План и заметки — в задачу (`--plan`, `--append-notes`), не в
переписку: задача переживает сжатие контекста и смену сессии.

**5. Проверить.** Прогон на самом высокофидельном доступном контуре, назови
на каком; UI — по рендеру. Внешний API/SDK/устройство или новый элемент в
существующей поверхности → `derflow/_gates.md` целиком. Каждый выполненный
критерий — `--check-ac <n>`. Непроверенное — «НЕ проверено — что, риск».

**6. Ревью до владельца.** `/code-review` на дифф задачи. Итог
(`--final-summary`) в таком порядке: **Ждёт тебя** (решения, одобрения, НЕ
проверено) · **Сделано** · **Найдено**.

**7. Закрыть.** Обнови доку capability — то, что теперь истинно, а не
рассказ, как к этому шли. Затем `~/.claude/scripts/bl-done.sh <ID>`. Доке
действительно нечего добавить → `--no-doc "<почему>"`. Коммит: задача, дока и
код вместе.

**Бросить недоделанное** → `bl-lock.sh drop <ID>` (вернёт в To Do, снимет
замок) + заметка, где остановился.

## Backlog: «не сейчас» всегда с причиной и сроком

```
backlog task create "<что>" -s Backlog --due-date <когда пересмотреть> \
  -d "<почему не сейчас и что должно случиться>"
```

Если событие проверяется машиной — добавь в описание блок пробы:

    ```when
    host: mprz          # local по умолчанию
    cwd: /home/deralsem
    match: pay_for_event
    ---
    journalctl -u bot-gmp --since today
    ```

На старте сессии хук `bl-wake.py` печатает созревшее (🟢), наступившие сроки
(📅) и недошедшие пробы (⚪) из кэша и обновляет кэш в фоне. Созревшее
переводит в To Do **только владелец** или его прямая просьба.

## Перенесено из derflow без изменений

- Вторая задача, родившаяся из работы (находка диагностики, фикс после
  консультации), — новой сессией через `hand.sh`; хендофф = файл задачи.
- Веер сабагентов: потолок до запуска, `<N> × $5 ≈ $<итог>`.
- Команды для ВДС — по правилам глобального `CLAUDE.md`.

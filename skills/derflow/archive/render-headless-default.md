# Рендер — headless по умолчанию, Vivaldi владельца — исключение (25.09.2026)

## Промах

Канон `_gates.md` велел снимать рендер через claude-in-chrome, а `shot.mjs`
держал запасным ходом «когда `captureScreenshot` в Vivaldi висит». Вышло
наоборот тому, что нужно владельцу: сессии открывали вкладки в его рабочем
браузере, под его учётками, посреди его работы. Жалоба владельца 25.09.2026,
решение принято им же.

## Числа

- `shot.mjs`, headless-shell: 0,9–1,1 с на снимок локального файла с запуском
  браузера (замер 25.09). claude-in-chrome на том же снимке висел до таймаута.
- `--mobile` = 390x844, плотность 2, touch; PNG 780x1688 — проверено.
- `--auth <имя>`: storageState из `tools/shot/auth/<имя>.json` (вне git, 0600);
  cookie доезжает до страницы, без флага — нет (проверено на localhost).
- `--save-auth <имя> <url>`: окно Chromium Playwright (Chrome for Testing), не
  Vivaldi; состояние пишется каждые 2 с и при закрытии окна.

## Правило

Проверка UI — `shot.mjs` (headless, при нужде `--auth`/`--mobile`).
claude-in-chrome — только (а) боевая админка под живой учёткой владельца,
(б) владелец сам сказал «посмотри у меня». Автоподключение браузера к сессии
(`claudeInChromeDefaultEnabled`) выключено, чтобы соблазна не было.

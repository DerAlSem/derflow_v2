# derflow · движок Lane C — openspec

Читается на полосах **C**, **C-bootstrap**, **C-adopt**, **C-drain**; полоса без движка — угадывание.
`openspec/` локальный в каждом репо; формат артефактов держит его схема (`schemas/<name>/schema.yaml`
плюс `templates/`) — она источник правды. Здесь — маршрутизация, дисциплины и гейты; рассказы, замеры и версии — в `archive/`, вне рантайма.

```
brainstorming → /opsx:explore → /opsx:propose
  → check.py → [ОДИН круг критики] → сведение → механика
  → /opsx:apply → свип «код против спеки» → /opsx:archive
```

## Цикл → archive/lane-c-cycle.md

- Замысел не твёрд — `superpowers:brainstorming` ПЕРЕД `explore`: он проверяет замысел
  против человека, круг критики — спеку против КОДА. Один другого не подменяет.
- `/opsx:explore` в openspec не пишет ничего: читай `openspec/specs` ПЕРВЫМ, затем только
  тот код, который фича мигрирует.
- Свой репо со спекой незнакомым не является: не веерь агентов «замапить архитектуру» и
  никогда не читай одни и те же файлы агентами И руками — платишь дважды.
- `/opsx:apply` — реализация ПЛЮС гейты derflow (TDD, ревью, verification-before-completion
  — `_gates.md`): у самого openspec их ноль.
- Дизайн оказался неверен — `/opsx:update` при том же замысле, новая заявка при изменившемся.
- `/opsx:verify` не заменяет verify-гейт `_gates.md`: тот требует ЗАПУСТИТЬ построенное.
- Многосессионная заявка — держи спеку живой через `/opsx:sync`, не копи слияние до архива.
- Схема или контракт: миграция, back-compat и откат В СОСТАВЕ задачи, не голой правкой.

## Reap-гейт: заявка жнётся, а не бросается → archive/reap-gate.md

- Полоса кончается на `openspec archive <id>` — он вливает дельту в живую спеку, — а не на
  «задачи отмечены». Каталог заявки руками не переносить.
- **`--yes` — только при нуле незакрытых задач**; счётчик машинный: `openspec list --json`,
  completedTasks/totalTasks. Флаг превращает блокировку CLI в строчку лога.
- ⚠️ **Третьего маркера у задачи НЕТ, и половинчатость пишется ТЕКСТОМ.** Замер 18.09.2026:
  `- [~]` выбрасывает строку из ИТОГА — `14 / 59` стало `14 / 56`, три задачи исчезли не из
  выполненных, а из ЗНАМЕНАТЕЛЯ, молча. Тот самый машинный счётчик строкой выше тогда врёт в
  сторону «готово». Тупик, который не годится тем более: ставить `- [x]` и оговаривать
  остаток прозой — недоделанное считалось бы сделанным.
- Незакрытая задача — это работа ИЛИ отказ, а отказ оформляет ЧЕЛОВЕК до архивации (снять
  из `tasks.md`, причина в `proposal.md`). Ветки «подтвердил и поехал» нет.
- В счёт идёт работа и проверка, а не ритуал закрытия: вопрос «выполнимо ли ДО архивации».
- `## Purpose` (50+ знаков) — ВЫШЕ блока `## ADDED Requirements`; `MODIFIED` несёт ПОЛНЫЙ
  блок требования со всеми сценариями. Иначе архивация теряет содержимое молча.
- `hooks/openspec-critique-gate.sh` ловит текст `openspec archive` в ЛЮБОЙ Bash-команде и совпадёт
  на ЧУЖОЙ живой заявке из сообщения коммита, а чужой круг снимать нельзя: сообщение пиши файлом
  и подавай `git commit -F <файл>`. Порядок: все правки `specs/` → отметка → жатва.
- Незажатые заявки называет счётом `hooks/openspec-reap-gate.sh`.

## Lane C-drain → archive/c-drain.md

- Цель — не «заархивировать всё», а сделать живую спеку правдивой: archive утверждает
  дельту КАК ИСТИНУ, и врущая толстая спека хуже честной тонкой.
- Триаж до всякого свипа (`grep`/`wc`): нет `tasks.md` → черновик, вон из `changes/`;
  0/N и старая → желание, в бэклог, НЕ в спеку; 100% → в свип; частичная — последней.
- Порядок вытеснения берётся из git (ID бездатные); вытесненную отбраковывай, не вливай.
- Свип ДО архива по SHALL'ам самой заявки: все `backed` → архивируй; смешанно → влей
  подтверждённое, остальное пометь `unbacked`; всё `unbacked` → в бэклог; `contradicted` →
  громче всех. Справочник — `~/.claude/skills/_conformance-sweep.md`.
- Отсутствие `normative` baseline тут НЕ блокер: вопрос «реализует ли код то, что дельта
  утверждает». Потолок ДО фанаута — «`<N>` воркеров × `$5` ≈ `$<итог>`», НЕ в токенах:
  токенная форма занижает счёт в ~100 раз (замер: 918 воркеров, дециль 9 — $10).

## Спека читается первой → archive/spec-first.md

- «Сломалось / ведёт себя не так»: `openspec/specs/<capability>` → `changes/` → потом код.
- Код против спеки = права спека, пока не решишь обратное СОЗНАТЕЛЬНО: тогда это Lane C с обновлением SHALL, а не тихая правка кода под факт.
- Нет спеки → почини по коду и напиши `descriptive` SHALL на затронутую capability, не на весь seam; скажи прямо: задокументировал задним числом.
- ID заявки — бездатный `<short-kebab>`: дату добавляет archive, CLI отвергает имя с цифры.

## Внешние API и контракты → archive/external-contracts.md

- Wire-контракт (вендорский референс или захваченный сэмпл) — ДО парсера и до вердикта о
  том, чего внешний API «не умеет». Сам гейт — в `_gates.md`.
- Маркетинг (позиционирование, ICP, оффер, цена, копирайт) — НЕ SHALL'ы: openspec держит
  поведение и контракт сайта, а не то, что сайт говорит.

## Входы в openspec → archive/openspec-entries.md

- Нет `openspec/` — `openspec init`: bootstrap, не блокер и не откат к дизайн-докам;
  приземляется на переходе explore→propose. Новая подсистема авторится напрямую.
- Меняешь существующую неспецированную сшивку — пиши дельту на изменение: спека густеет по
  трафику, а не по решению задокументировать всё заранее.
- `docs/superpowers/specs` — датированная история, не со-живущая спека: проверяй её против
  текущего кода и оставляй на старом доке supersede-указатель.

## Критик-слой → archive/critic-layer.md

- **Круг положен только заявке, трогающей деньги, права или ПД**; остальным — одна механика.
  Форма слоя: механика → ОДИН круг → сведение → механика.
- Круг один, УЗКИЙ и парой (`system-architect` + `gap-finder`): мишень — новые нормы, код,
  их исполняющий, и СОСЕДНИЕ модули поимённо. Слой закрыт ПО СЧЁТУ, а не по признаку;
  второго круга нет, перенос в сабагентов кругом быть не перестаёт → archive/critic-ceiling.md.
- ДО круга — механика, её вывод идёт критику ВХОДОМ как установленные факты:
  `python3 ~/.claude/scripts/check.py .` и `grep -c '^#### Scenario:' <спека>`.
- ПОСЛЕ сведения — снова механика, а не второй критик: дифф ИМЁН сценариев против базы, `git diff --stat`
  заявки, греп по числам в `proposal.md`/`design.md`, `check.py`. `LC_ALL=C` — перед КАЖДЫМ процессом конвейера
  (`sort`, `comm`, `uniq`), иначе врут на кириллице в обе стороны; у пропавшего имени — НАЗВАННЫЙ преемник.
- Резолюции сопоставляй N → SHALL чтением `spec.md`: «закрыто» на слово ревьюера не
  принимается, проза `design.md` не связывает и переоткроется на реализации.
- Отметку круга ставь СРАЗУ после сведения: `hooks/openspec-critique-record.sh <id>`. Второй
  круг и несвежую отметку держит `hooks/openspec-critique-gate.sh`.
- Свип «код против спеки» — ДО архивации, критик его НЕ заменяет (текст против текста) → archive/critic-narrow-circle.md.
  Потолок до запуска, обязателен опровергающий проход, затем злой по выжившим — в его задание кладётся
  «не убивай подгонкой: ложное убийство хуже ложной находки» — и счёт по уровням: косит ровно — сломан.
- Многостадийная процедура СТАРТУЕТ, только если промежуток переживает сессию: вердикт воркера — ФАЙЛОМ
  рядом со спекой, наверх строка. Не переживает — отказ стартовать: умершая на середине стадия врёт «не сделана».
- Зелёный `openspec validate` не доказывает ничего: не читает прозу `MODIFIED`, не видит второй
  `.md` в каталоге capability, молчит на переименованном заголовке и на `MODIFIED` требования,
  которого в живой спеке НЕТ ВОВСЕ. Правишь требование, приезжающее с архивацией СОСЕДА, — сторож
  не памятка, а `grep -q` заголовка плюс строка `waiting.py` → archive/validate-blind-spots.md.
- По каждому SHALL: «какая НЕВЕРНАЯ реализация это удовлетворяет?» — есть ответ, переписывай
  → archive/shall-against-breakage.md.
- В промпт круга кладётся «пустой ответ ценнее выдуманной находки»; находку критика И его
  лекарство проверяй по коду — критик, которого позвал ты сам, авторитетом не становится.
- Утверждение о коде проверяется кодом — особенно СОБСТВЕННОЕ и особенно severity (её цена куплена
  состоянием ДАННЫХ, строка лога с «или» фактом о машине не является) → archive/claims-verified-by-code.md.
- Принесли предназванный подход вместо проблемы — frame-challenge `system-architect` ДО деталей.

## Ошибки этой полосы → archive/lane-c-mistakes.md

- «Ещё один круг», «узкий добор», «финальная сверка критиком», «свежая редакция не критикована» — слой закрыт: гони механику и открывай `tasks.md`.
- Круг находит дефекты в СТОРОЖАХ — сигнал срезать сторожей, а не недокритикованность.
- Гнать не тот «explore» или оба сразу: Lane C explore — дизайн по живой спеке, Orient `explore-code` — разведка НЕзнакомого репо.
- Анонсировать openspec и сдрейфовать в `docs/superpowers/specs` + `writing-plans`:
  переутверждай полосу на переходе explore→propose, а не только в анонсе.
- Гнать заявку в `openspec/changes` в репо с `backlog/config.yml` — там заявка
  живёт в Backlog.md (скилл `docflow`), openspec закрыт с 24.09. Роутер правило

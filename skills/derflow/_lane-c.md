# derflow · движок Lane C — дисциплины полосы

Читается на полосах **C**, **C-bootstrap**, **C-adopt**, **C-drain** и **Dx**. Хранилище заявки здесь не
главное: в репо с `backlog/config.yml` заявку, замки и доки ведёт скилл `docflow`, ниже — только то, что от
хранилища не зависит. Остальное про `openspec` (цикл `/opsx:*`, reap-гейт, C-drain, входы) —
`archive/lane-c-openspec.md`: читается, пока репо ещё на `openspec/`; репо с openspec переносятся на backlog
(`scripts/bl-migrate.py`). Рассказы, замеры и версии — в `archive/`, вне рантайма.

## Спека читается первой → archive/spec-first.md

- «Сломалось / ведёт себя не так»: дока capability (`backlog/docs/capabilities/`, в репо на openspec —
  `openspec/specs/<capability>`) → заявки по ней (`backlog search`, `changes/`) → потом код.
- Код против спеки = права спека, пока не решишь обратное СОЗНАТЕЛЬНО: тогда это Lane C с обновлением SHALL, а не тихая правка кода под факт.
- Нет спеки → почини по коду и напиши `descriptive` SHALL на затронутую capability, не на весь seam; скажи прямо: задокументировал задним числом.
- ID заявки — бездатный `<short-kebab>`: дату добавляет archive, CLI отвергает имя с цифры.

## Внешние API и контракты → archive/external-contracts.md

- Wire-контракт (вендорский референс или захваченный сэмпл) — ДО парсера и до вердикта о
  том, чего внешний API «не умеет». Сам гейт — в `_gates.md`.
- Маркетинг (позиционирование, ICP, оффер, цена, копирайт) — НЕ SHALL'ы: openspec держит
  поведение и контракт сайта, а не то, что сайт говорит.

## Критик-слой → archive/critic-layer.md

- **Круг положен только заявке, трогающей деньги, права или ПД**; остальным — одна механика.
  Форма слоя: механика → ОДИН круг → сведение → механика.
- Круг один, УЗКИЙ и парой (`system-architect` + `gap-finder`): мишень — новые нормы, код,
  их исполняющий, и СОСЕДНИЕ модули поимённо. Слой закрыт ПО СЧЁТУ, а не по признаку;
  второго круга нет, перенос в сабагентов кругом быть не перестаёт → archive/critic-ceiling.md.
- ДО круга — механика, её вывод идёт критику ВХОДОМ как установленные факты:
  `python3 ~/.claude/scripts/check.py .` и `grep -c '^#### Scenario:' <спека>`.
- ПОСЛЕ сведения — снова механика, а не второй критик: дифф ИМЁН сценариев против базы, `git diff --stat`
  заявки, греп по числам в `proposal.md`/`design.md`, `check.py`. `LC_ALL=C` — перед КАЖДЫМ процессом конвейера
  (`sort`, `comm`, `uniq`), иначе врут на кириллице в обе стороны; у пропавшего имени — НАЗВАННЫЙ преемник.
- Резолюции сопоставляй N → SHALL чтением `spec.md`: «закрыто» на слово ревьюера не
  принимается, проза `design.md` не связывает и переоткроется на реализации.
- Отметку круга ставь СРАЗУ после сведения: `hooks/openspec-critique-record.sh <id>`. Второй
  круг и несвежую отметку держит `hooks/openspec-critique-gate.sh`.
- Свип «код против спеки» — ДО архивации, критик его НЕ заменяет (текст против текста) → archive/critic-narrow-circle.md.
  Потолок до запуска, обязателен опровергающий проход, затем злой по выжившим — в его задание кладётся
  «не убивай подгонкой: ложное убийство хуже ложной находки» — и счёт по уровням: косит ровно — сломан.
- Многостадийная процедура СТАРТУЕТ, только если промежуток переживает сессию: вердикт воркера — ФАЙЛОМ
  рядом со спекой, наверх строка. Не переживает — отказ стартовать: умершая на середине стадия врёт «не сделана».
- Зелёный `openspec validate` не доказывает ничего: не читает прозу `MODIFIED`, не видит второй
  `.md` в каталоге capability, молчит на переименованном заголовке и на `MODIFIED` требования,
  которого в живой спеке НЕТ ВОВСЕ. Правишь требование, приезжающее с архивацией СОСЕДА, — сторож
  не памятка, а `grep -q` заголовка плюс строка `waiting.py` → archive/validate-blind-spots.md.
- По каждому SHALL: «какая НЕВЕРНАЯ реализация это удовлетворяет?» — есть ответ, переписывай
  → archive/shall-against-breakage.md.
- В промпт круга кладётся «пустой ответ ценнее выдуманной находки»; находку критика И его
  лекарство проверяй по коду — критик, которого позвал ты сам, авторитетом не становится.
- Утверждение о коде проверяется кодом — особенно СОБСТВЕННОЕ и особенно severity (её цена куплена
  состоянием ДАННЫХ, строка лога с «или» фактом о машине не является) → archive/claims-verified-by-code.md.
- Принесли предназванный подход вместо проблемы — frame-challenge `system-architect` ДО деталей.

## Ошибки этой полосы → archive/lane-c-mistakes.md

- «Ещё один круг», «узкий добор», «финальная сверка критиком», «свежая редакция не критикована» — слой закрыт: гони механику и открывай `tasks.md`.
- Круг находит дефекты в СТОРОЖАХ — сигнал срезать сторожей, а не недокритикованность.
- Гнать не тот «explore» или оба сразу: Lane C explore — дизайн по живой спеке, Orient `explore-code` — разведка НЕзнакомого репо.
- Анонсировать openspec и сдрейфовать в `docs/superpowers/specs` + `writing-plans`:
  переутверждай полосу на переходе explore→propose, а не только в анонсе.
- Гнать заявку в `openspec/changes` в репо с `backlog/config.yml` — там заявка
  живёт в Backlog.md (скилл `docflow`), openspec закрыт с 24.09. Роутер правило
  знает, движок полосы — нет: сверяй маркер ДО открытия `openspec/`. Боевое
  01.10.2026: Lane C оформила выкат в openspec-заявку через неделю после
  запрета (gmb_v2 bb56a504b).

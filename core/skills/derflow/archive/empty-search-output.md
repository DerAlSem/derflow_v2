## Пустой вывод поиска — не находка, пока не проверен код возврата (v4.19)

Утверждение «этого нигде нет» опирается на инструмент, а инструмент бывает не
запущен. Отличить «не нашёл» от «не искал» глазами нельзя: и то и другое
выглядит как пустой вывод.

📏 Боевое, mprz.ru 05.09.2026, поиск секретов по всей истории (2141 коммит).
Оболочка здесь `zsh`, и она **не разбивает на слова раскрытие переменной** —
в отличие от подстановки команды:

```
REVS=$(git rev-list --all); git grep -E '…' $REVS   # все 2141 хеш ОДНИМ аргументом
git grep -E '…' $(git rev-list --all)                # правильно: 2141 аргумент
```

Первая форма падает с `rc=128` и пишет в stderr. Под `2>/dev/null` — которое
стоит там ровно затем, чтобы не тонуть в «not a valid object» по служебным
ссылкам, — отказ невидим. **Три скана из шести соврали пустотой:** приватные
ключи, DSN с паролями и присвоения секретов «не нашлись». Переигранные те же
три нашли четыре DSN и три пароля, включая тот, что стоял sudo-паролём двух ВПС.

Названный отказ: в `bash` эта форма работает, поэтому рецепт из чужой памяти
или из привычки переносится молча и ломается только здесь.

Тупик, который стоит исключить сразу: **переписывать регексп бесполезно** — он
был верен с самого начала, не запускался сам поиск.

📏 Правило узкое и проверяемое одной строкой: **у поиска, чей пустой вывод стал
доводом, проверь `rc` и не глуши stderr.** Пустой вывод при `rc=0` — находка;
при любом другом — не искал.

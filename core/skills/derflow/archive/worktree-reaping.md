# Жатва ворктри: вторая половина v3.9 (архив derflow, глава _parallel до 13.09.2026)

## Ворктри вырезаются — и жнутся, когда мержатся

v3.9 говорит создать; без второй половины они **накапливаются молча** (сессия
слепа и к оставленному сёстрами). Ворктри, чья ветка полностью влита в `main`, —
мёртвый груз: он делает `git worktree list` нечитаемым, прячет, какая работа
реально живая, и хоронит handoff-доки среди устаревших деревьев. **Жатва
принадлежит завершению задачи** — тот же момент, что
`superpowers:finishing-a-development-branch`, а не периодическая уборка:

```
git worktree remove <path> && git branch -d <branch>   # -d откажется, если не смержено: это и есть страховка
git worktree prune                                     # подмести записи об удалённых каталогах
```

`-d`, не `-D`. Форс-удаление уничтожает ровно ту страховку, ради которой шаг
существует.

Скрэтчпадные/detached ворктри под `/tmp/.../scratchpad/` принадлежат своей сессии
и умирают с ней — удаляй их в конце задачи, которая их создала. Чтобы
проаудировать утечку, классифицируй, а не считай:
`git merge-base --is-ancestor <branch> origin/main` → смержено = жнётся. (Боевое:
gmb_v2 дорос до 24 ворктри; 11 из 18 веточных были полностью влиты в `main` —
мертвы — плюс 3 detached скрэтчпадных от законченных сессий.)

## Сессия в снимаемом ворктри теряет шелл (27.11.2026)

Механизм. ztui (zcode-cli 0.18.0-2) заводит шелл каждого вызова Bash заново с
cwd = рабочий каталог сессии и не проверяет, существует ли он:
`core/src/tool/handlers/bash.ts:549–553` →
`adapters/src/exec/node-execution-adapter-run.ts:327` (в клоне `~/dev/ZCode`,
под `apps/zcode-cli/packages/`; снято 27.11.2026 по коду). Каталога нет —
`spawn /bin/zsh ENOENT`. Вызов падает, успешной записи cwd обратно не бывает,
и `workingDirectory` с `workspaceRoot` остаются на умершем каталоге до конца
сессии. Файловые инструменты (Read, Edit, Write по абсолютному пути) живут.

Боевое: 24.11 (C·18.1 — шелл умер посреди разговора, когда преемник снял её
ворктри), 25.11 (wb-tails), 26.11 (wb-heredoc), 27.11 (wb-blwake, дважды с
интервалом) — четыре сессии за четыре дня. В трёх последних порядок «жатва
последним вызовом» держали нарочно, и первый же вызов после неё падал; в
первой хендофф предполагал работу после снятия.

Порядок до патча. Всё, чему нужен шелл, — до снятия: закрытие задач, оба ff,
пуш, `./install.sh --check`, пометка корневого хендоффа, память. Сама жатва —
последний вызов инструмента, одной командой с `cd <корень>` в начале и с
печатью итога в том же вызове (status, worktree list, date). Строку
«✅ Исполнено … ворктри снят» — в том же вызове, после успешных remove и -d:
умри сессия между пометкой и жатвой, в корне останется «сняты» при живом
ворктри.

Подъём. `Write`-заглушкой пересоздать каталог (Write делает родительские) —
шелл возвращается; каждый вызов начинать с `cd <корень>`: каталог заглушки —
стартовый, cwd в корень не переносится. Заглушку снять последним шагом
последнего вызова.

Исключённый тупик: «выйти cwd в корень до hand.sh» не спасает — `hand.sh
<ворктри>` открывает таб преемника в самом ворктри, и жать приходится тому, кто
в нём стоит. Обходной путь, проверенный 27.11 (C·хвосты-будильника): хендофф с
«ветка: main» в корень, преемник режет ворктри сам — его стартовый каталог
корень, снятие ворктри шелла не трогает. Цена: относительные пути файловых
инструментов уходят в корень, работать только по абсолютным.

Названный отказ: правило про свою сессию. Чужая, стоящая в твоём ворктри,
для тебя слепа — её шелл оно не спасает. В Claude Code не воспроизводилось и не
проверялось.

Патч причины — в клоне ZCode (решение владельца 27.11.2026: патч + строка
канона): стартовый каталог исчез → шелл заводится из ближайшего существующего,
`workingDirectory` переносится, `workspaceRoot` остаётся идентичностью
сессии, в контекст — заметка. Хендофф клона —
`.claude/handoff/shell-cwd-fallback.md`. Думали: когда патч в живом бинаре —
строку из `_parallel.md` снять, этот раздел оставить историей. Вышло иначе —
раздел ниже.

## Патч в живом бинаре: строка осталась с другим смыслом (28.11.2026)

Что оказалось. Патч в `main` клона ZCode (`32815647`, ztui 0.18.0-4), спека —
`docs/runtime-tools/bash-missing-working-directory.md` там же. Каталог
проверяется на входе каждого вызова инструмента (до PreToolUse-хуков, прав и
хендлера) и ещё раз после хендлера, до PostToolUse-хуков: `ENOENT` или
`ENOTDIR` — исполнительский `workingDirectory` уходит вверх, до ближайшего
существующего каталога. `workspaceRoot` не меняется: сессия остаётся собой —
`$CLAUDE_PROJECT_DIR`, память проекта, project id прежние. Каталог не
пересоздаётся, файлы не переносятся.

Снимать строку не стали: шелл патч возвращает, файлы ворктри — нет. Владелец
одобрил строку с другим смыслом («ок», 28.11.2026): стартовый каталог исчез —
исполнение переносится, вызовы Bash и их хуки выживают; хендофф всё равно
пишется до снятия ворктри. Правило «жми последней командой», подъём заглушкой
и обходной путь «хендофф в корень» с 0.18.0-4 шеллу больше не нужны; цена
прежняя — файлы ворктри, хендофф в их числе, снятие не вернёт.

Проверка. Headless-прогон новым билдом 28.11, 07:49 — четыре вызова: `pwd` →
D; `rm -rf -- <D>` проходит, одна заметка D → F; `pwd` → F;
`$CLAUDE_PROJECT_DIR` → прежний D. `PostToolUse` на самоудаляющем вызове —
success (до правки — `spawn /bin/sh ENOENT`). Таб ztui глазами владельца,
~08:00: `rm -rf -- "$PWD"`, следом `pwd` → родитель. Журнал CLI
(`~/.zcode/cli/log/zcode-2026-11-28.jsonl`) несёт оба переноса:
`tool.working_directory.relocated` в 07:49:40 и 08:02:29.

Названный отказ. Переносятся только вызовы инструментов и их хуки. Файлы
ворктри, `process.cwd()` CLI, стартовые каталоги stdio-MCP и хуки уровня
запроса (SessionStart, UserPromptSubmit) остаются на прежнем каталоге. Табы,
открытые до первой пересборки с патчем (28.11, 07:37), его не имеют — для них
действует порядок до патча из раздела выше. В Claude Code не воспроизводилось
и не проверялось.
